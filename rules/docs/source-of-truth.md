# Source-of-truth writing

Every file is a clear, complete statement of the current intended design, behavior, or decision.

- Edit authoritative content in place. Do not append commentary narrating a previous version or how the current one supersedes it.
- Avoid "this supersedes the earlier proposal", "previously", "we used to", unless the file is explicitly a changelog, migration guide, or historical record that needs that history.
- Remove or revise obsolete alternatives, abandoned approaches, and stale instructions so readers meet one coherent source of truth.
- Keep rationale that explains the current decision, stated as rationale for the current choice, not editing history.
- History-tracking files follow their own purpose and format. Never turn ordinary plans, specs, or instructions into history trackers.
- Before finishing a write, reread the affected sections and remove residue from earlier drafts: contradictions, duplicated guidance, transition notes.
